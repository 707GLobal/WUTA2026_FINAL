# WUTA-SIM连接、记录与算法链分析

## 启动

本机模拟器依赖 `/home/wuta/lyx/WUTA/WUTA-SIM/install/setup.bash`。可用 SIM_SETUP 指定另一份已安装模拟器；本项目算法 overlay 最后加载，使用当前 WUTA2026_FINAL 的算法二进制。不会调用旧项目的“一键停止全部进程”工具，也不启动真实CAN、ZLG、相机或雷达驱动。

```bash
cd /home/wuta/WUTA2026_FINAL
./start_wuta_sim_validation.sh
./start_wuta_sim_validation.sh --mission acceleration --duration 40 --speed 2
./start_wuta_sim_validation.sh --mission trackdrive --duration 60 --speed 4
./run_wuta_sim_regression.sh
```

单次默认限时40秒并自动生成记录目录。Ctrl-C或结束会关闭本次启动的子进程，保留记录。禁止默认硬件域0，默认使用localhost的ROS域157；同一域同一项目只能启动一个测试。若发现已有其他节点，拒绝混接；可设置 WUTA_SIM_DOMAIN=158。

故障参数 `--fault` 可选 velocity_dropout、pose_dropout、empty_path、nan_path、emergency。路径故障先暂停规划发布者，再注入空或非法路径；定位故障暂停定位管理器，车速断流只停止适配层转发速度。故障从本次时长55%开始，不自动恢复急停。

## 历史接入背景（2026-10-11）

- 原车辆模型直接按 `Command.speed` 内置比例控制，不消费 `throttle_brake`，无法证明当前速度PID有效。本地 EffortVehicle 适配用开度推导加速度，继续使用原模型转向惯性和横向动力学；不是实车辨识模型。
- 原模拟器轴距1.53米、最大转角25度，与当前算法1.614米、28度不同。测试车辆从控制模块配置读取两项几何参数。
- INS原话题为 `/cg410/odometry`，本项目使用 `/chcnav/odometry` 与 `/chcnav/velocity`。测试重新指定输出话题，并转发车体速度。
- 模拟赛道使用旧的“左蓝右黄”，当前算法要求“左红右蓝”。测试仅在无红锥且有蓝/黄两组时转换赛道副本，所有模拟传感器读取同一副本；原赛道不修改，转换记录存为track_contract.json。
- 相机输入是模拟检测框/颜色/深度，并非真实图像YOLO推理。仿真关闭任务管理器的图像心跳检查，保留模拟雷达和惯导检查；该分支不能证明真实相机断线自检。
- 未启动真实CAN接口；执行器标定表和VCU控制报文需要另做虚拟CAN/HIL与实车验证。

## 记录

每次保留控制和节点配置快照、赛道副本、启动命令、部分可执行文件哈希、每节点stdout日志、telemetry.csv、轨迹文件、rosbag及summary.json。最早的基线包只记录了链路关键输出；后续测试增加了点云、模拟相机检测、CameraInfo、TF和急停输入。固定INS种子42不意味着所有模拟模块完全确定性复现。

批次入口生成 results.txt 和 report.md；失败工况保留，不覆盖成通过。评估包括：收到控制命令、真实运动、完整链路输入、有限数值、目标速度上限、实测车速容差、转角/开度范围，以及故障后的预期零指令。直线横向偏差门限为1.5米，是测试报警阈值，不是车道碰撞或赛规安全标准。

## 算法链与参数风险

| 链路 | 当前仿真验证与需要注意的参数 |
|---|---|
| 点云→雷达锥桶 | 仿真使用模拟地面对应的高度滤波；不能直接把实机M1的RANSAC参数照搬。聚类尺度、最小簇数、高度范围决定漏检/误检 |
| 模拟相机→融合 | 投影、颜色和时间关联参与链路；真实YOLO、真实遮挡与深度偏差仍未覆盖。fixed_frame、sync_slop_sec、颜色阈值及坐标约定必须一致 |
| INS→EKF→定位 | INS带噪声，当前不启用KISS。检查15维状态选择和过程噪声；反馈接收超时不等同于GPS/主机采集时钟同步 |
| 定位+锥桶→地图 | 静止定位噪声会累计行程，已发现原算法误闭环；现在额外要求离开起点至少2倍闭环半径。累计里程仍受噪声影响，正式圈数及完整赛道闭环需要继续验证 |
| 地图→边界 | 左右颜色必须满足当前红/蓝约定。有效点数不足、方向错误、跨支路配对可能导致无路径或急转，不应通过放宽所有门限掩盖 |
| 边界→规划 | 直线锚点是绝对map坐标；循迹目标还受曲率、置信度、起步和路径长度限速。默认直线速度15米/秒，不能据2米/秒测试认定全部高速工况可靠 |
| 规划→控制 | 增加定位超时、非法定位/路径/输出检测、空路径停指令；赛项切换清PID积分。PID开度、前视关系及曲率分位数现在启动检查，防止无效参数导致越界 |
| 控制→车辆 | 模拟开度作用于代理加速度模型。正常车速上限为测试配置覆盖，不自动写回实车配置；使用各赛项原PID。反馈丢失释放驱动，不等同主动制动 |
| 急停→执行器 | 当前controller急停输出全零，模拟模型会滑行减速；本次测试只验证指令归零，不能据此认定EBS停车距离或制动力达标 |

## 新增的控制保护

定位超过control.pose_timeout_sec（默认0.5秒）未更新、非法位姿、空/非法路径、非有限控制输出时，不继续保留原行驶目标。会回正并发布零目标速度，若车速仍有效则由当前速度闭环给制动输出；缺少有效车速时输出中性开度。

CAN旧指令重发风险已增加接口侧超时保护，但进程退出、通信断流等仍应由VCU独立的命令超时和RES/EBS链处理，不能靠ROS参数保证。此测试没有验证VCU独立保护。高噪声工况触及28度转角限幅，仍需按实际定位噪声、执行器带宽与速度优化前视及控制参数。

通过有限片段与边界检查不能保证车辆永不出现速度/方向异常。完整多圈、路面/轮胎变化、迟延与重启、车辆碰撞几何、真实感知/CAN及实车制动仍需要专门验证。

## 此次额外发现及复核

- 15米/秒直线首次最高15.70米/秒，超过0.6米/秒测试容差；增加PID抗积分饱和后重测，最高14.81米/秒并停在175米目标附近，进入FINISH。零目标时禁止噪声微分项产生正驱动。
- 180秒循迹达到MAPPING_DONE和RACE。原“最近离散航点距离”检查失败（3.44米），保留原失败结果。rosbag复核显示规划只发布前方窗口，最差样本前方首点距离3.44米，但到首段延长线的垂距0.30米。另存geometry_review.json：线段距离检查仅对第一段允许最多5米向后延伸，未放宽1.5米报警门限；全段最大距离1.03米、最大方向差28.27度。该值仍不证明车身在真实车道内，需要独立车道边界、车辆宽度与碰撞检查。
- CAN接口新增control.command_timeout_sec（默认0.5秒），非法/超时命令不再重发旧驱动；发送中性开度、回正和Signal3离线。首份控制消息之前不发控制帧。真实VCU是否按离线请求可靠制动仍需硬件验证；心跳与离线状态的组合行为也需核对。

原车辆模型发布的车体横向速度为0，侧滑速度的反馈一致性尚未验证；不同轮胎/路面与真实车辆参数需要后续辨识。

配置入口现已迁回FSD各模块config；此文前面的统一配置描述属于历史运行背景。最新来源与仿真覆盖见[实车模块配置加载逻辑](实车模块配置加载逻辑.md)。

2026-10-12：统一速度调试入口已移除，仿真 `--speed` 写入规划模块的对应赛项快照，控制器使用各赛项PID。历史验证结果不代表本次修改后的验证结果。
