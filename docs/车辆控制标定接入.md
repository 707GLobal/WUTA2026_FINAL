# 车辆控制标定如何接入算法


> 2026-10-12 状态更新：`can_interface` 已回退到 `54a6038`。当前仅支持原线性编码和 `steer.max_steer_angle`，已移除标定表、命令超时保护及其测试。总启动检查核对控制器的 `vehicle.max_steer_angle` 与 CAN 的 `steer.max_steer_angle`。下文标定表接入说明保留为历史方案，当前版本不能按该步骤启用标定表。

## 入口与运行行为

控制参数在 `WUTA-FSD/ros2_ws/src/control/controller/config/controller.yaml`，执行器标定、CAN最大转角和命令超时在 `system/can_interface/config/can_interface.yaml`。
全车分别加载模块文件，不读取主目录历史统一配置。两个模块的最大转角需保持一致；启动检查会核对。
详细来源见 [实车模块配置加载逻辑](实车模块配置加载逻辑.md)。

首次代码接入需要编译控制器和 CAN 接口两个软件包；本次已执行构建。之后仅修改 YAML，重启相关节点即可，无需重新编译。参数在构造函数中读取，没有实现运行中热加载。

默认两张标定表均为 `enabled: false`，文件数值来自原配置/协议，不代表新实测数据。启用前应替换为测量结果。默认线性编码、PID、滤波与车辆尺寸保持原值。

全栈默认加载模块文件，可通过 `--controller-config` 与 `--can-config` 明确选择其他模块配置。`--sensor-only` 不启动控制器/CAN 接口节点，因此不消费此文件。

## 数据流

控制器按赛项使用 `pid.*` 调节速度闭环，`throttle.max_opening` / `brake.max_opening` 分别限制驱动与制动开度，目标速度在规划模块按赛项设置。统一速度调试入口已移除。详见 [分赛项速度调试](直线调试与简单速度控制.md)。

```text
规划目标速度/路径
    ↓
controller_node：轴距 → 纯追踪算法 → 等效前轮转角（度）
                 速度误差 → PID → 归一化纵向开度（-1..1）
                 转向限幅/限速，目标速度平滑
    ↓ /control/command
can_interface：转角 → 标定表插值 → Signal2
               纵向开度 → 标定表插值 → Signal1
    ↓ 0x210（原有大端字节序）
VCU
```

## 测量结果填哪里

| 测量/辨识结果 | YAML 字段 | 用法 |
|---|---|---|
| 前后轴距，米 | `vehicle.wheel_base` | 改变路径曲率到转角的计算 |
| 允许的等效前轮最大角，度 | `vehicle.max_steer_angle` | 控制器与 CAN 层共用限幅 |
| 实际等效前轮角与 Signal2 配对 | `steer.calibration.angle_deg` / `signal2` | 非线性逆映射，取代原线性转角编码 |
| 归一化纵向作用量与 Signal1 配对 | `longitudinal.calibration.effort` / `signal1` | 可选静态开度修正，取代原线性开度编码 |
| 转向响应支持的变化率，度/秒 | `control.max_steering_rate_deg_s` | 对转角指令限速；不是延迟补偿 |
| 平滑系数 | `control.accel_alpha` / `decel_alpha` | 系数范围 0..1，控制目标速度平滑，不是物理加速度 |
| 速度阶跃试验调出的增益和输出限制 | 各赛项 `pid.kp/ki/kd/integral_limit` 及 `throttle.max_opening` / `brake.max_opening` | 速度闭环控制 |

安装转向比不需要单独乘到这个链路中：控制器输出已是前轮等效角，标定表应直接映射到 VCU 的 Signal2。不要把方向盘角直接填成前轮角，也不要同时在 VCU 和上位机重复乘转向比。

## 转向表怎么整理

1. 记录 `Signal2、左前轮角、右前轮角、上扫/下扫、负载状态`。角度相对实际直行零位，左转为正。
2. 将左右轮角换算成与控制器自行车模型匹配的等效转角。例如理想低速阿克曼转向几何，在两轮转向同号且非零时，可用 `cot(delta_eq)=(cot(delta_left)+cot(delta_right))/2`；角度进入三角函数前转为弧度，零位单独处理。最终用低速圆周半径检验，`delta_eq=atan(L/R)`，R 对应后轴中心轨迹。存在明显侧滑时不应套用低速几何检验。
3. 按等效角从负到正排序，相应 Signal2 从大到小排列，两个数组一一配对。必须包含实测零角点。
4. 将各行分别填入 `angle_deg` 与 `signal2`，设置 `enabled: true`。
5. 将 `vehicle.max_steer_angle` 设置在左右标定覆盖范围内。如果左右极限不同，当前控制器使用较小绝对极限作为对称限幅。

当前 YAML 中的三点是原线性协议值：

```yaml
steer:
  calibration:
    enabled: false
    angle_deg: [-28.0, 0.0, 28.0]
    signal2: [65535.0, 32767.0, 0.0]
```

实际测得多少点就填多少点，不限于三点。算法在相邻点之间分段线性插值，超出表范围钳位，不外推。零位可以对应实测的非 32767 Signal2，用于静态零位修正。

启用表时检查配对长度、有限数值、至少三个点、实际零点、严格单调、CAN 范围及车辆角度覆盖范围；不合法会在打开 CAN 设备前拒绝启动。非有限指令退回标定零位。

## 纵向数据怎么用

现有 PID 输出的是 `throttle_brake`（归一化开度），不是目标加速度。因此不能直接把 `m/s²` 填入 `effort`。

先做低速、固定工况的阶跃测试，保存 `时间、Signal1、速度、纵向加速度、载荷`：

- 起步最小有效指令、制动死区、延迟及随速度变化的响应，用于调 PID 与评估模型。
- 若确实需要静态非线性修正，可在明确工况和归一化基准后，把期望的纵向作用量映射到实测 Signal1。驱动/制动各自归一化，输入范围仍是 [-1,1]；零点必须是 `0 → 32767`，避免停车/急停零开度被表格变成驱动输出。
- 不做该修正时保持 `longitudinal.calibration.enabled: false`，直接调各赛项 PID；这已经可以使用测量后的响应数据。

这张表不提供物理加速度前馈，也不包含速度/载荷维度。若需要 `目标加速度、车速 → 油门/制动`，还需扩展控制接口和多维车辆响应模型。单一工况的测量表不能宣称覆盖全部车速。

回差、执行器纯延迟不能靠单值静态表完整补偿；应分别保存到试验记录，后续按需要增加有状态回差模型或延迟补偿。当前没有添加仅存储但不被算法消费的“延迟参数”。

## 验证与保存

1. 保存原测量 CSV、车辆/设备编号、日期、负载、测量方法及标定版本。
2. 先核对空载静态转角和零位，再验证负载下响应，最后低速验证圆周半径、速度跟踪和制动。
3. CAN模块新表启用后重新评估 PID；执行器映射变化会改变闭环增益。
4. 用 `ros2 param get /controller_node vehicle.max_steer_angle` 和 `ros2 param get /can_interface vehicle.max_steer_angle` 核对两个节点收到同一限幅；用 `ros2 param get /can_interface steer.calibration.enabled` 核对表状态。

代码验证覆盖非线性插值、边界钳位、零点、非有限指令、无效表拒绝和原三点线性映射的协议值一致性。构建/参数加载验证不代表实车物理标定完成。
