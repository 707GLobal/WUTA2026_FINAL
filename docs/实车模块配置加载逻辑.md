## 优先级

源码默认值 → 对应模块YAML → 用户明确指定的部署选项。

全车感知使用新的 `fusion_modules_hardware.launch.py`，直接把模块YAML交给节点，不再用硬编码的阈值字典覆盖雷达/融合配置。相机模型路径需解析成绝对路径，唯一的额外相机参数是解析后的model_path；其他相机算法参数来自模块文件。原 `fusion_hardware.launch.py` 保留为旧独立调试入口，其参数覆盖行为没有改变，不是全车脚本的入口。

`--model=FILE` / 环境变量MODEL可以明确更换模型；未指定时读取相机模块model_path，相对路径以该YAML所在目录解析。CAN_IFACE明确指定时覆盖CAN设备并同步用于桥接；未指定时读取CAN模块的can.device。

`--controller-config=FILE` 与 `--can-config=FILE` 可明确选择模块配置的其他版本。旧 `--vehicle-calibration` 会拒绝并提示迁移；旧 VEHICLE_CALIBRATION 不再使用并给提示。

物理外参的部署路径、TF发布者选择、进程启停仍由脚本负责，保留 `--calibration`、`--base-to-zed`。算法阈值不由这些部署选项覆盖。控制器和CAN的最大转角必须一致；跨节点话题必须一致；当前全车不启动NDT，不能开启NDT比赛定位，否则参数检查明确报错。

## 检查与留档

```bash
./start_full_fsd.sh --print-config   # 不检查硬件、不启动节点；输出文件来源与参数JSON
./start_full_fsd.sh --check          # 模块配置检查后继续检查设备
```

每次实车启动保存 `wuta_logs/<赛项或pending>/<YYYYmmdd_HHMMSS>/configs/module_config_manifest.json`，包含源文件、解析参数、模型与CAN设备，以及是否显式覆盖。更改模块文件后重启节点生效；从源码config直接读取，无需为单纯YAML调参重新编译。首次增加新launch/配置时需安装更新，本机已完成。

主目录统一控制 YAML 及 `config/` 中的兼容链接已于2026-10-12删除，只保留控制器和CAN模块配置。`perception/config/field_tuning.yaml` 也是旧共享调参入口，全车不自动读取；直接改上表的模块文件。

## 行为保持与仿真

2026-10-12已移除统一控制限速和纯比例调试入口，速度及PID分别回归规划/控制模块的各赛项配置。保留现有赛项数值、车检、执行器标定和固定超时保护；此前硬件launch实际使用的相机1280×768、置信度0.25、雷达RANSAC/0.08米体素、融合颜色阈值0.6和关闭位置融合已写入各模块文件。

仿真读取控制模块配置后创建本次测试快照，`--speed` 仅覆盖本次规划快照的对应赛项速度（默认2米/秒），不再提供 `--mode` 控制算法选择。由于雷达模块现以实机M1参数为准，仿真明确覆盖模拟点云话题、仿真地面高度滤波与0.1米体素；融合也明确关闭引导聚类、改用仿真点云话题。仿真覆盖被保存在每次测试快照中，不改写模块文件。

运行目录、配置副本和赛项结束归档规则见 [运行日志](LOGGING.md)。
