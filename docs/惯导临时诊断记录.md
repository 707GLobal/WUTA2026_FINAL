# 惯导临时诊断记录

2026-10-13复核，记录10月12日工作。临时诊断功能只增加已有驱动中的计数，不增加串口读者、不改变协议或发布门槛。
独立的GNSS策略修改已将桥的默认门槛由1改为0；不能将诊断插桩与门槛调整混为一项变更。
通过已有ROS执行器的1秒定时器写入JSONL，即使串口无数据、主解析循环等待字节，也能记录零输入状态。

## 使用

当前华测驱动已重新构建。下一次启动 `./start_fsd_manager.sh` 或原 `./start_full_fsd.sh` 会默认启用。
全栈运行的记录位于本次运行目录：

```text
wuta_logs/<赛项或pending>/<YYYYmmdd_HHMMSS>/chcnav_log/diagnostics/
  parser.jsonl
  protocol.jsonl
  bridge.jsonl
```

若运行结束后日志归档，记录跟随运行目录移动。独立华测启动脚本则在其日志目录下生成
`diagnostics_<YYYYmmdd_HHMMSS>_<PID>/`。使用 `--reuse-ins` 不会改变已经运行的外部惯导进程。

关闭临时记录：

```bash
FSD_INS_DIAGNOSTICS=0 ./start_fsd_manager.sh
```

也可通过 `CHCNAV_DIAGNOSTIC_DIR` 给独立华测链路指定已有/可创建的日志目录。
目录为700权限。初始化记录失败只提示并禁用诊断，不影响原驱动运行。

## 字段

每条记录带 `epoch_ms`、`stage`、实际 `interval_ms`、最后输入/输出距今毫秒数。
`input_age_ms=-1` 代表该节点尚未观测到输入；`output_age_ms=-1` 代表未记录到输出。
`delta` 是距上次记录的增量，`total` 是本进程累计计数。未用于该stage的字段保持0。
串口为非阻塞读取，包间的 `empty_reads` 增长是正常现象；应结合每秒 bytes 和 input_age 判断断流，不能仅凭空读次数报警。

| 文件 | 重点字段 |
|---|---|
| parser.jsonl | bytes、read_calls、empty_reads、read_errors、parse_errors、cgi_frames、nmea_frames、nmea_xor_errors、nmea_tail_errors |
| protocol.jsonl | cgi_received、crc_ok、crc_errors、message_id、pvt_length_errors、pvt_published |
| bridge.jsonl | pvt_received、gnss_status、gnss_rejected、nonfinite_rejected、stdev_rejected、odometry_published、velocity_published |

注意：parser的`cgi_frames`仅表示组帧成功，不代表CRC有效。CGI的CRC结果以protocol文件为准。
`parse_errors`是组帧/同步等解析错误次数；不能把它全部叫作CRC错误。
`odometry_published`表示publish调用成功返回，不保证下游已接收到消息。
parser阶段的output_age未统计ROS发布，仅使用bytes、input_age和帧数判断。

## 判断方法

- bytes=0且input_age持续增大：读取位置没有收到字节。
- bytes持续增加但cgi_frames=0、parse_errors增加：收到数据，但协议组帧失败。
- cgi_frames增加但protocol的cgi_received不增加：检查发布/订阅、DDS和协议节点状态。
- crc_errors增加：CGI校验失败；message_id为最后收到的消息号（0x1201的十进制为4609）。
- crc_ok增加但pvt_published=0：检查是否输出了期望消息ID、pvt_length_errors。
- pvt_published增加而bridge的pvt_received不增加：检查devpvt的DDS链路/桥进程。
- pvt_received增加但odometry_published=0：查看GNSS或数值拒绝计数。

定时记录每秒flush，崩溃前最后不足1秒的计数可能未落盘。空文件或长时间没有记录本身也可能表示
节点/执行器未启动、阻塞或退出，不能将其直接解释成串口0字节。

## 无硬件验证

在正确加载ROS和华测工作空间环境后执行：

```bash
/usr/bin/python3 -m pytest -q humble-chcnav-cgi_ros2pkg/src/chcnav/test/test_temporary_ins_diagnostics.py
```

测试通过file输入制造“完全无数据”和“有字节但协议错误”两种情况，不读取真实串口、不发送控制命令。

17:38:03那次devpvt/odometry/velocity都为0，上游原因未确定；退出时的-11在停止信号之后出现，应单独处理。
