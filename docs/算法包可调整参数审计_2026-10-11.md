# 算法包可调整参数审计（2026-10-11）

> 参数入口已更新为各模块config；此前统一文件/旧硬件launch覆盖的描述为历史背景。当前来源以[实车模块配置加载逻辑](实车模块配置加载逻辑.md)及最新JSON/CSV清单为准。


本次只检查源码、配置与启动关系，没有修改算法参数，没有连接实时节点或启动车辆。全栈值按 `start_full_fsd.sh` 的默认启动路径推导，未考虑用户另传命令行参数或环境变量。不能将这些值视作当前运行进程的实读值。

扫描范围为 WUTA-FSD/ros2_ws/src 的算法及系统包，包括 Python/C++ 两种实现、robot_localization 和 KISS-ICP；控制独立 YAML 也纳入。设备驱动配置列为附件，外部驱动完整参数不在本仓库源码内，不宣称已穷尽。消息包与工具包没有可运行的调参节点。

统计按“软件包+参数名”合并；相同名称在不同节点中的含义和默认值可能不同，JSON 保留各声明位置；传感器编号模板及配置实例均计入，因此数量不等于独立物理调参旋钮数。成员默认值无法可靠还原的保留源码表达式，不猜测数值。

## 主要结论

1. 当前全栈没有加载 `perception/config/field_tuning.yaml`。改变该文件不会改变这条启动路径。感知参数以硬件 launch 默认值与其显式覆盖为准；根脚本进一步指定推理尺寸 1280×768、关闭感知内部建图和 ZED 动态 TF。
2. 当前控制器和CAN分别读取各自模块配置；主目录统一控制 YAML 及兼容链接已于2026-10-12删除。两个模块的 `vehicle.max_steer_angle` 必须一致，启动检查会核对。
3. 当前全栈的相机置信度为 0.25；融合颜色概率门限为 0.6；雷达 RANSAC 距离门限 0.08 m、体素边长 0.08 m；位置融合关闭，引导局部聚类开启。这些值不能仅从包内原 YAML 推断。
4. 硬件 launch 内部启动地图时覆盖 `assign_colors=false`、语义颜色纠正开启、确认次数3；全栈关闭这个内部地图节点，另启动地图节点，实际读取 `assign_colors=true`，语义纠正默认关闭、确认次数1。两条启动路径行为不同，调参时应先确认入口。
5. 本项目自定义节点通常在构造函数中把参数复制到成员变量，没有找到参数更新回调。运行中 `ros2 param set` 即使改变参数服务器的显示值，也不能据此认定算法已更新。应修改配置后重启节点。
6. 雷达 `detector_type=dl` 虽然可填写，但 DLDetector 构造函数直接抛出“尚未实现”；当前只能使用 traditional 后端。
7. 立体深度筛选、部分置信度模型和调度周期仍是源码常量，无法只靠 YAML 调整，详见下表。
8. 解析的16份独立 ROS 参数文件（另检查2个兼容路径）均通过本机 rcl 参数语法检查。自定义算法配置没有发现找不到源码声明的参数名（已展开动态名称，并按实际消费者归属配置）。这不代表数值范围、物理标定或运行链路均已验证。
9. 第三方示例配置保留了15处 `*_nodelay` 项，但当前本地源码未声明/读取这些名字；navsat 示例的 `broadcast_utm_transform_as_parent_frame` 与源码旧参数名末尾下划线不一致。它们不在当前全栈启用路径中，切换到示例配置时应清理/核对。
10. 全栈未启动 KISS、清洗器、NDT 和地图点云保存器，EKF 配置仍订阅 `/kiss/odometry_sanitized`。这是未接入的可选输入，不应将 KISS 参数当作当前定位的生效调参项。

## 生效层级与容易误解的参数

- 控制器和CAN：源码默认 → 各自模块 YAML → 显式命令行覆盖。
- 感知：源码默认 → 包内 YAML → 硬件 launch 参数字典；根脚本传入的 launch 参数决定该字典最终内容。field_tuning.yaml 在当前入口无加载步骤。
- ground_z_threshold 在非 RANSAC 去地面或 RANSAC 失败回退时使用，当前开启 RANSAC 不代表该参数完全无用。
- 融合的 lidar_sigma、reference_sigma 也参与几何关联/协方差处理；关闭位置融合不意味着两者不生效。max_position_shift 仅限制位置融合带来的位移。
- 图像推理的 model_input_width/height 要匹配模型引擎；不必等于相机发布的图像尺寸，框坐标需要正确还原到原图。
- boundary_detector.desired_velocity 是上游中心线速度；最终车速由 path_generator 的赛项速度、曲率、置信度、路径长度和起步限速共同决定。
- map_origin 只声明/校验路径锚点，不发布 TF，也不会重设华测 ENU 原点。
- path_generator 的 driven_trajectory.* 只控制显示轨迹，record.* 只控制离线落盘；不直接改变定位、建图或控制。
- trackdrive 参数只在对应赛项/阶段生效；acceleration、ebs、skidpad 和 inspection 也有独立参数，不能只调一套 PID 后认为覆盖所有赛项。

## 校验与范围检查

下列关系是代码现有检查或应满足的调参约束；不是实车性能已达标的证明。

| 参数组 | 检查结果/约束 |
|---|---|
| 相机置信度/重叠框抑制 | 代码检查位于(0,1)，线程数正整数，推理尺寸同时为零或同时为正 |
| 雷达 RANSAC | 迭代≥1，概率(0,1)，地面倾角(0,45]已有检查；体素/聚类尺度、簇点数及高度上下限缺少统一启动校验 |
| C++ 融合 | 正数、有限值、队列、概率、簇点数与高度关系有较完整检查；Python 备选实现的检查较少，切后端不能假定所有保护相同 |
| 车辆控制 | 轴距、最大角度正且有限；平滑系数[0,1]；转角变化率非负；控制频率正整数已有检查；PID 增益/限幅已新增有限值、非负及开度不超过1的启动检查 |
| 执行器标定表 | 启用时检查长度、零点、有限值、单调性、CAN 范围及转角覆盖；纵向必须保持零开度对应32767 |
| 路径生成 | 大量值在使用处钳位；没有完整启动校验，错误填写可能被静默改写。例如采样间距≤0.05跳过重采样，>0.05但<0.2会按0.2使用 |
| 赛道边界/地图 | 缺少成组有限值、正数、上下限关系启动校验，部分值在使用处限定；建议核对最小/最大宽度、比例范围、合并距离与锥桶间距 |
| 任务管理 | 需核对自检超时/宽限、置信度[0,1]、圈数与计圈几何；当前配置有真实传感器检查，关闭检查不应当作普通性能调参 |
| EKF | 配置数组应为15个布尔值，过程噪声为225个值；通过文件解析不等于协方差正定、量级合理或传感器时间同步已验证 |

## 尚未开放成 YAML 的重要常量

| 位置 | 当前常量 | 影响 |
|---|---|---|
| 立体适配器 | 图像/深度容差10 ms，最多等50 ms，历史队列20，处理周期10 ms | 深度可用率和输出延迟 |
| 立体位置估计 | 框中心40%区域、至少6点、有效比例≥60%、深度0.3～40 m | 深度点筛选 |
| 立体位置估计 | 深度10～90%跨度≤max(0.3 m,0.08×深度)；噪声下限0.03+0.0015×深度² | 深度有效性及协方差 |
| localization_manager | 置信度 exp(-0.5×平面位置方差-2×偏航方差) | 定位置信度与下游速度/状态门控 |
| 地图节点 | 发布周期200 ms等调度值 | 发布节奏，未开放成 ROS 参数 |
| 多个节点 | 部分 ROS 话题、队列深度、TF 等待值和几何保护常数 | 可以通过 ROS 重映射改变部分话题，不能只写 YAML 改算法常量 |

优先完善：统一感知参数入口、明确两种地图启动方式的颜色策略、补充 PID/聚类/地图/边界的范围校验，再按实测需要开放立体阈值及定位置信度模型。暂不根据静态审计自行改车辆速度、制动或传感器门限。
