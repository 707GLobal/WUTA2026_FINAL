# 任务机职责迁移说明

> 核对基准：`WUTA-FSD/ros2_ws` @ `2b945f3`（分支 `小登测试`）。下文"现状位置"均指该版本的实际代码。

## 原则

任务机（`system/mission_manager`）只负责**任务切换**；定位与建图的**计算/判定**归还对应模块，任务机只读取结论。

## 保留（任务机本职）

- 状态机迁移：IDLE → READY → INSPECTION / EXPLORE → MAPPING_DONE → RACE → FINISH → EMERGENCY
- 任务模式设置（订阅 `/system/mission_mode_cmd`）与 `/system/mission_state` 广播（10Hz，含 `state` / `mission_mode` / `localization_mode`）
- **发车门控**：已选模式 + `/system/start_command`（RES 0x1E4 Byte1=0x13）→ 由 READY 进 EXPLORE / 进 INSPECTION
- **完成回报**：`/system/mission_complete` → FINISH；Trackdrive 以 `/system/lap_count` 为准，忽略外部完成信号
- 急停：订阅 `/system/emergency` → EMERGENCY；自检失败时任务机也向该话题发布
- 车检（inspection）流程
- **传感器自检（L2）**：三传感器（lidar/imu/camera）心跳监控 → 故障即切 EMERGENCY + `/system/devices_inspection`
- 消费外部结论：`/planning/global_centerline_ready`（全局中心线验收）作为 RACE 门槛

## 迁出：→ `localization`

| 内容 | 现状位置（`mission_manager`） | 迁移目标 |
|---|---|---|
| 定位模式切换（KISS-ICP ↔ NDT） | `transitionTo` 写 `localization_mode_` → `/system/mission_state.localization_mode`；`use_ndt_race_localization` 参数 | `localization_manager` 自主决定（现状仅被动读取该字段） |
| 定位置信度门槛 | `advanceRaceWhenReady`，订阅并保存 `/system/localization_confidence` | `localization` 判定并对外给结论 |
| 定位新鲜度判定 | `advanceRaceWhenReady`（`last_pose_received_at_` + `localization_timeout_sec`） | 同上 |
| NDT 地图就绪门槛（`/ndt/map_ready`） | `onMapReady` 订阅；发布者为 `ndt_localization/map_saver` | 并入定位就绪结论 |
| 圈次统计（由 `/localization/pose` 计圈） | `updateLapCounter` / `publishLapCount` | `localization`，发布 `/system/lap_count`（话题名不变，换发布者） |

对外接口收敛为**单个结论布尔** `/system/localization_ready`，其内部综合置信度、新鲜度、NDT 就绪；任务机只读该布尔。

> 现状：`/system/localization_ready` 已由 `localization_manager` 发布，但目前仅表示"位姿有效"（pose 有限且非 FINISH/EMERGENCY），**尚未**聚合置信度/新鲜度/NDT 就绪；`/system/localization_confidence` 仍由任务机与 `path_generator` 消费。

## 迁出：→ `mapping/cone_map_builder`

| 内容 | 现状位置（`mission_manager`） | 迁移目标 |
|---|---|---|
| 建图质量评估（颜色平衡 / 平均置信度 / 最少锥数） | `coneMapQualityPasses`；参数 `min_red_cones` / `min_blue_cones` / `min_map_average_confidence` / `min_map_color_balance` | `cone_map_builder`，经 `ConeMap` 字段或独立话题给出结论 |
| 建图相关日志（`Cone map closed` / `quality failed`） | `onConeMap` | 随质量评估一并移走 |

> 现状：`ConeMap.msg` 仅含 `is_closed`，无质量结论字段；质量由任务机按红/蓝锥数量、平均置信度、颜色平衡计算。

## 连带修改

1. **断环**：`cone_map_builder` 现于正式圈次达标时闭合（`onLapCount` → `/system/lap_count >= mapping_laps`），并以纯几何回环（`checkLoopClosure`）兜底；迁移后删去对 `/system/lap_count` 的依赖，仅保留几何回环 + 显式"探索完成"信号。
2. **圈次换主**：`/system/lap_count` 发布者由任务机改为 `localization`；消费方 `cone_map_builder`（冻结地图）、`path_generator`（RACE 圈速选择）以及任务机自身（FINISH 判定）改为订阅它做门控/限速。
3. **质量结论上移**：`ConeMap.msg` 增加质量结论（字段或话题），任务机只读。
4. **定位结论聚合**：`localization_manager` 输出单一 `localization_ready`（内部聚合置信度/新鲜度/NDT 就绪）；任务机删除 `min_localization_confidence`、`localization_timeout_sec`、`/ndt/map_ready`（`onMapReady`）、`use_ndt_race_localization` 相关逻辑与参数。
5. **模式切换反置**：任务机广播任务阶段/请求（如"请求进入 RACE"），NDT/KISS-ICP 取舍由 `localization_manager` 决定（现状为任务机写 `localization_mode`、`localization_manager` 被动跟随）。
6. **lidar_ready 收编**：L2 自检已归任务机（`lidar_last_seen_` 心跳），但 IDLE→READY 仍以 `/system/lidar_ready` 为门槛，而该话题在仓库内**无发布者**（悬空输入）；改为用自检的 lidar 心跳产出"lidar 在线"，删除该订阅。

## 迁移后任务机的形态

从"生产 + 消费"退化为纯"**消费结论 + 状态迁移**"。
