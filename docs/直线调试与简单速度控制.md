# 分赛项速度控制与直线跑偏排查

## 速度和开度调参入口

2026-10-12恢复 `54a6038` 的分赛项调参布局，已移除统一速度调试参数和纯比例控制分支。

- 目标速度：`path_generator/config/path_generator.yaml` 中 `acceleration.speed.velocity`、`ebs.speed.velocity`、`skidpad.speed.velocity`，以及 `trackdrive.speed.*`。
- 速度PID和开度限制：`controller/config/controller.yaml` 中对应赛项的 `pid.kp/ki/kd/integral_limit`；对应赛项 `throttle.max_opening` 和 `brake.max_opening` 分别限制驱动和制动开度。
- 横向跟随：控制器对应赛项的 `pure_pursuit.*`。
- 车检：仍使用 `inspection.throttle` 等独立参数。

没有额外统一目标速度上限。车速反馈超时0.5秒或无效时纵向开度归零，定位超时0.5秒仍触发保护；这两项为内部固定保护，不是额外调参入口。CAN命令超时由CAN模块管理。

修改对应模块YAML后重启节点生效。不要把输出开度当成固定加速度或车速。

## 直线不直，先判断哪一层出了问题

先在低速下同时查看实际轨迹、规划直线和控制转角；物理轮角必须通过实测或有效执行器反馈确认，不能把 `/control/command.angle` 当成实测转角。

| 现象 | 优先检查 | 应调整的数值 |
|---|---|---|
| 控制转角为0，车辆仍固定向一侧偏 | 前轮真实零位、前束/定位、轮胎/胎压、执行器回差、路面横坡 | 先修正机械状态；实测直行零位对应的 `steer.calibration.signal2`，不要先改前视距离 |
| 指令左转但实车右转 | 控制角左正约定、CAN编码和VCU执行方向 | 核对协议/执行器方向；不能靠改轴距或最大角掩盖符号错误 |
| 刚起步就持续要求较大转角 | 规划直线是不是沿正确的车道方向，定位yaw和坐标系是否一致 | 校验路径锚点和华测航向；需要时修改 path_generator 的 `acceleration.anchor.entry/brake/stop` |
| 转角指令正负反复变化，轨迹左右摆 | 前视过短、定位或横向速度噪声、执行器滞后 | 直线加速时逐步增大 `acceleration.pure_pursuit.min_lookahead` 或 `lookahead_ratio`；循迹时检查其 `min_lookahead/max_lookahead` 和动态前视 |
| 偏出去以后回正很慢，但零位/航向正常 | 前视过大、目标点太远、转向限速过低 | 适当减小对应赛项前视，核对 `control.max_steering_rate_deg_s` 是否低于实测响应能力 |
| 低速直、高速偏或振荡 | 时间延迟/不同步、安装外参、杆臂、横向速度噪声、执行器带宽 | 先降低 规划模块对应赛项速度 重复比较，再验证时间同步和转向延迟；不要只加大控制增益 |
| 规划线本身歪或弯 | 锥桶地图、相机雷达外参、车辆参考点、路径锚点 | 先修正定位/标定/规划；控制器会追随这条歪线 |

一次只改一个数值，比较相同速度下的横向误差、航向误差和转角变化。更大前视通常更平滑，但回正更慢、转弯跟随也会改变，不能认为越大越好。[MathWorks 纯追踪说明](https://www.mathworks.com/help/nav/ref/controllerpurepursuit-system-object.html)

## 当前项目中特别要核对的两个点

### 直线加速锚点参考系

当前 `acceleration.anchor_frame` 可选择 `start_pose` 或 `map`。前者以启动时冻结的定位位姿转换路径锚点，后者使用地图绝对坐标。核对该赛项的 entry/brake/stop，不能只改某个 yaw 就认为路径连线方向改变。

### 控制器在一定车速以上使用速度航向

`course_speed_threshold` 默认0.5米/秒；超过该门限时，控制航向为 `yaw + atan2(vy,vx)`。如果华测的车体横向速度vy有噪声或坐标轴错误，直线也可能表现为转角抖动。

先记录 vx/vy/yaw。必要时暂时提高对应赛项的 `course_speed_threshold`，在同一低速工况比较使用纯yaw后的效果；这只用于辨别问题，不能代替横向速度/安装轴标定，也不应永久屏蔽真实侧滑信息。

## 需要补齐哪些实测标定

1. **直行零位**：Signal2→左右前轮角，重点加密零附近的数据，并分别测正反方向回程。找到真实直行角对应的CAN值，填到 `angle_deg=0` 配对点。
2. **近零转向比例、死区与回差**：除了左右满转角，还要测小角度响应。静态表只能处理单值非线性与零位，不能完整补偿随方向/负载变化的回差。
3. **转向响应变化率和延迟**：记录命令与真实轮角，确定可跟随的转向变化率；据此设置 `control.max_steering_rate_deg_s`。纯延迟不能仅靠静态表消除。
4. **华测安装角、双天线定向和杆臂**：确认设备输出确实对应后轴中心。已知方向下检验yaw，比较车辆前进/左转的速度和角速度符号。角偏置只用于有依据的残差修正。
5. **真实轴距与车辆坐标外参**：`vehicle.wheel_base` 应填实测值；M1与车辆的2.33米、同轴同高约定也要核实。最大转角用于限制转向，不能修正直行零位。
6. **速度反馈与纵向响应**：与独立速度参考比对，测驱动/制动死区、响应与延迟，帮助调节对应赛项的PID和开度限幅。
7. **相机、雷达、惯导时间关系**：动态验证投影/定位是否随着速度出现偏差。接收时间一致不等于采集时间一致。

ROS地理坐标约定为朝东yaw=0、逆时针为正；应确认设备和转换代码满足同一约定。[ROS REP-103](https://github.com/openrobotics/reps/blob/main/_posts/rep-0103.md)

## 建议记录的数据

同步记录 `/planning/final_waypoints`、`/localization/pose`、`/chcnav/velocity`、`/control/command`；另保存实测轮角与实际车道基准。区分：规划目标速度、滤波后目标速度、实测车速、控制器转角、真实前轮角。

已有路径记录功能可保存部分轨迹和命令。改变控制模块速度配置后需要重启控制器；路径锚点在规划包配置中，修改后也需重启规划节点。
