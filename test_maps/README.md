# 测试路径地图

正常全车测试会自动启动只读地图采集，按采集会话分别保存到本目录；传感器模式、制动台架和人工记录模式不自动采集。独立复盘也默认使用本目录。这里是规划路径和行驶轨迹的可视化结果，不是占据栅格地图。

```text
test_maps/<运行目录名>_<采集时间>_<唯一编号>/
├── capture.json             # 来源运行目录和输出说明
├── observations.jsonl       # 增量原始观察记录，可恢复/回放
├── map.svg                  # 最近一个已导出任务的地图，浏览器直接打开
├── segment_001.svg          # 各任务分段的完整地图
└── segment_001.json         # 样本数量、缺失输入等状态
```

蓝色点线是当前最终路径，灰色为历史路径版本，黄色为标准定位轨迹，紫色为原始惯导轨迹，红点为最新标准定位位置。图中 X/Y 单位为米，等比例显示；断流、时间回退和定位跳变会断开实际轨迹连线。路径版本之间不连线，不推测正式圈数。

活动任务默认每2秒更新地图，在任务复盘冻结、切换任务或采集器正常退出时也导出。只有实际收到的数据才能被记录；请在 GO 前启动。强杀或断电后可用完整 JSONL 行恢复地图：

```bash
bash fsd-visualization-code/review.sh --replay /绝对路径/observations.jsonl --export-only
bash fsd-visualization-code/review.sh --replay /绝对路径/observations.jsonl --segment 1
```

第一条仅导出所选分段（默认最后一段），不初始化 ROS 节点或打开窗口；第二条在 RViz 回放。SVG 可直接用浏览器打开，无需 ROS。无有效任务分段时不会导出地图，不会生成模拟结果。采集器日志和输出路径分别在原运行目录的 `artifacts/mission_review.log` 和 `artifacts/mission_review.ready`。

原有 CSV 仍在 `wuta_logs/<赛项>/<运行时间>/trajectory/`，未移动或更改。已安装的 ROS/FSD 消息环境仍是采集/回放命令的依赖。RViz 原有坐标系和视角不变。本目录的测试数据子目录不提交 Git。


## 已知限制（2026-11-05核对）

当前提交保留以下两个已用隔离小例子复现的问题，尚未修复；它们影响复盘准确性/完整性，不改变驾驶输出。

- **延迟旧Lane可覆盖当前路径。** add_plan未检查任务起始时间或版本先后；例如任务起始t=20，先收t=21路径，再收延迟t=11路径，后者仍成为当前显示路径。等待TF的旧路径随后补到也可能触发该问题。
- **结束边界的待TF目标可能静默丢失。** 目标在任务活动时收到并等待TF，任务结束/急停后TF才补齐时，队列项被移除，但目标因已进入draining阶段不写入目标历史或未转换记录，也没有对应丢失告警。因此“已收到”或warning未增加都不能证明目标完整。

长任务完整历史驻留内存，变化图层发布完整快照，内存、DDS消息大小及SVG导出成本随样本/路径版本增长；50ms调度不保证固定帧率。采集开始前未收到的数据不回填，强杀或断电可丢失最后一次刷新之后的数据。复盘停稳判断不等于硬件停车验收。
